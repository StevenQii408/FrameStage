# 完整事件视频提示词交付 v2

2026-11-09 补充：新渲染器的紧凑正文以 [可复制 Prompt 交付 v2](prompt_delivery_v2.md) 为准。单阶段不强制秒数，流程／审计说明移入合同，首帧无声音或收束段；下文保留既有证据和事件纪律，不作为历史文本自动改写指令。

本文件补充 `seedance_video_prompt_skill.md` 和 `action_delivery_v1.md`，仅适用于合并后的 GenerationSequence / 事件 Agent GenerationClip，不改变原始拆镜或事件合并规则。

## 结构

```text
【Seedance 生成序列提示词】
主体：完整事件中已观察到的人物、外形与固定道具。
场景：已观察到的地点与空间关系。
视频规格（生成设置）：时长 D 秒；分辨率 1080p；横屏 16:9 / 竖屏 9:16。
以首帧画面为起点：0 秒可见状态；保持角色、服装、道具、场景和光线一致。
动作时间线（生成编排建议，不是原片动作时间实测）：
0–A 秒：从首帧状态开始的动作与本段镜头安排。
A–B 秒：接续动作；需要切镜时，在本段直接写景别与焦段。
B–D 秒：后续动作与必要的反应。
整体画面风格：已确定的完整风格段落，只写一次。
声音：生成声音设置，不冒充原片音轨分析。
收束：最后一帧可见状态。
无台词，无人物说话，无旁白；不生成文字、字幕、Logo、水印或可读符号。
```

## 纪律

- 主体覆盖这一整段事件的已见参与者，不只取第一镜主体；首帧图片仍只描述首镜的静态状态，不提前加入后续人物或结果。
- 动作只写进对应时间段，删除独立的“叙事动作 / 主动作概述”。收束描述终态，不再复述整段过程。
- 多段按实际目标推进的少量语义阶段连续覆盖 0–D 秒；单一连续动作可只写 0–D 秒。递交、接杯、接稳通常可合为一个阶段，饮用及关联表情、停顿、再次饮用可组成另一个阶段。不能把所有事件强制为两段或四段，也不能按来源切点逐镜分配一段。
- 事件 Agent 的新阶段可带 `semantic_phase`，作为生成编排标签；动作仍逐字来自已验证保存事实，并按来源顺序完整呈现。相邻同名阶段只在连续承接、生成摄影方案相同且没有独立特写/揭示时聚合为一个生成阶段，累计原起止、全部来源与动作事实，不改变总时长、来源时间或完整来源分片。
- 必要的独立信息特写/揭示和明确生成切角保留独立 `cut` 阶段，摄影与动作同段展示。来源手部特写若只是完整递交动作的不同视角，可以融合；普通反馈可融入同目标阶段，关键事实、证据和来源不得丢失。
- 新 Agent 阶段可提供单行 `action_summary`（1–260字），以自然动作推进概括该段完整事实，保留递交、必要反馈、再次饮用等推进；总 Prompt 用此生成编排描述，完整原文事实、`fact_ids`、来源和帧证据继续保存在合同。摘要不得新增人物、道具、结果或因果，也不得在未分析音频时断言交谈、对白。整个阶段若被分到多个片段，各片段使用自己拥有的原事实，不把整段摘要错误复制到部分来源中。缺摘要的旧合同保持原正文。
- 摘要中的重点感官、生理/疾病、心理、因果和完成结果推断标签（如品尝、吹气、喘息、疲惫、中毒、疼痛、喝光/喝完/喝尽/一饮而尽）必须由本阶段已验证 `fact_ids` 对应的 `fact.text` 明确支持；目标、其他阶段、来源自由文本或未核实情绪不是支持。支持事实若均为“或/可能/似乎/无法判断”等不确定观察，摘要须保留不确定性，不能把闭眼撅嘴猜成品尝、嘴巴张合与汗珠猜成喘息或极度疲惫、饮用猜成全部喝完。缺支持会指明具体词，沿用最多一次纠错预算。
- 用完纠错预算后，只有摘要的无支持标签、确定化或对白错误可按字段停用摘要并回到完整原事实文本；原摘要和原因保留在审计，明确标记摘要需复核。重新完整验证通过后保留正确事件合并，事实、证据、来源归属或新人物/物件标签错误仍按原安全规则回退事件，不追加模型调用。
- 可用 `generation_subjects`（最多4项）与 `generation_objects`（最多6项）精确选择本事件已保存的主要人物/必要道具标签，减少重复外貌、背景家具等主体行噪声。选择只影响视频主体行，首帧仍独立描述0秒可见状态，源观察和追溯不变。
- 可选展示名单在解析后只保留本事件精确保存标签并去重，非空名单若全部非法则使用确定性来源描述；合法的显式空道具名单 `generation_objects=[]` 保持空选择，不回填背景道具、不新增警告。修复时原名单、移除项和警告写入审计，不为名单措辞增加模型调用。被移除的名称若同时出现在摘要、且无当前阶段原事实或保存标签支持，则停用该摘要；不猜角色别名。事实、证据、归属和场次规则继续严格验证。类型/长度等 JSON Schema 错误仍沿用既有修复预算，不放宽整个合同。
- 秒数是生成编排，不是原视频动作完成时间。原时间、原切点及完整追溯继续保存在合同，不混入可复制正文。
- 内部切镜的摄影描述与动作放在同一时间段；连续镜头可以用一个统一摄影段，不重复每段动作。
- 总时长取既有生成时间线，不因为修改格式重新切镜、合并或延长视频。
- 画幅优先用已有合同，再用首镜未裁剪帧尺寸；均不可用时采用竖屏 9:16 并标记默认生成画幅。
- 分辨率为生成设置，默认 1080p；已有生成设置优先。768px 等抽帧尺寸不是输出视频分辨率。
- 画风复用已保存结果，不重新识别，不添加未经证实的艺术风格。
- 旧任务仅做安全的只读格式投影，不写回历史、不改变节点 ID、来源归属、时间线、时长或合并哈希。缺少原始交付基线或检测到手工编辑时保留旧文本。

编排升级在既有事件 Agent 分析预算中执行；确定性阶段聚合不增加付费请求。旧任务缺少语义阶段名时保持既有阶段，不凭正文猜测重组，不接入视频生成 API。
